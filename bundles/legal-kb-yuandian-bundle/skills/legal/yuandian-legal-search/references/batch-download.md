# 元典批量法规下载

适用场景：
- 用户有法规清单（如积分使用记录里的建议清单）
- 需批量下载法规正文入库知识库
- 积分余额有限，需要精准下载避免浪费

## 核心坑（已踩）

**清单里的法规名称通常是简称/关键词，不是精确名称。**

例：
- 清单写"盗窃罪解释" → 匹配到"最高人民法院对...建议的答复"（通知类）
- 实际要的是"最高人民法院关于办理盗窃刑事案件适用法律若干问题的解释"

后果：用关键词搜索，64 条里只有 13 条是法规正文，51 条是通知/答复/批复。

## 解决方案

### 方案 A：已知名称时，先 `search` 再 `detail(id)`（新版默认）
不要再默认 `get_fagui_detail(fgmc=精确名称)` 直撞。实测会遇到两类坑：
1. 直接报“程序处理异常”
2. 命中成“关于印发……的通知”这类外壳文件

更稳的顺序：
1. `search_fagui(fgmc=精确名称, xljb_1=目标效力级别, sxx="现行有效")`
2. 若无结果，再降级为 `keyword=精确名称`
3. 本地筛候选：标题、效力级别、时效性、是否通知外壳
4. 只对高置信候选调用 `get_fagui_detail(id=...)`

```python
from yuandian_api import search_fagui, get_fagui_detail

results = search_fagui(
    fgmc="住宅专项维修资金管理办法",
    xljb_1="部门规章",
    sxx="现行有效",
    top_k=5,
)

if not results:
    results = search_fagui(
        keyword="住宅专项维修资金管理办法",
        xljb_1="部门规章",
        sxx="现行有效",
        top_k=10,
    )

for r in results or []:
    name = r.get('fgmc', '')
    if name == "住宅专项维修资金管理办法":
        detail = get_fagui_detail(id=r['id'])
        break
```

### 方案 B：主题性法规/地方法规/审理指南，先搜候选再本地筛
对“江苏执行异议审理指南”“参与分配指导意见”“行政审判指引”这类主题材料，不要靠单一标题硬撞。

更稳的做法：
- 搜索词用主题词组合，如：`执行异议 审理指南`
- 默认 `search_mode=AND`
- 先卡 `xljb_1`：`地方司法文件` / `地方性法规` / `地方政府规章`
- 再卡 `sxx=现行有效`
- 需要时加 `fbrq_start` 限近年材料
- 回来后本地按“江苏 / 江苏省 / 江苏高院 / 南京 / 无锡 / 苏州”等标题或发布机关二次筛选

### 方案 C：通知外壳不等于没价值，要看正文有没有附件规范
实测几个高频目标会命中成：
- `建设部关于印发《前期物业管理招标投标管理暂行办法》的通知`
- `江苏省物价局关于印发《物业服务收费明码标价规定》的通知`
- `江苏省人民政府关于印发江苏省政府信息公开暂行办法的通知`

处理口径：
1. 先看 `content` 是否带完整附件正文
2. 有完整规范正文：可保留并标记“通知外壳/附件型正文”
3. 只有通知壳、没有实质条文：标记 `通知外壳，不入主库`

### 方案 D：案例优先轻详情，别一上来就拉全文
结合接口文档，案例检索结果里的 `content` 往往已经够用：
- 权威案例：如果 `content` 已含裁判要旨 / 典型意义 / 指导意义，直接入库摘要版
- 普通案例：如果 `content` / `fxgc` 已含“本院认为 / 裁判分析 / 应当认定 / 不予支持”等实质规则，直接入库摘要版
- 只有当 `content` 太短、没有分析、明显只是程序结果时，才调用 `rh_case_details`

这条非常重要：**案例下载的省分，不在搜索，在少调详情。**

### 方案 E：江苏执行主题词搜案例，命中率可以，但精度一般，默认要二筛
实战补充：对 `执行监督`、`恢复执行`、`首查封`、`参与分配` 这类江苏执行主题，直接用 `search_ptal(qw=主题词, xzqh_p=["江苏"])` 能拉到一批材料，但会混入不少：
- 标题很泛的执行裁定书
- 只有程序动作、没多少规则密度的通知书
- 虽然命中关键词，但和你真正想补的程序桥接点关系不强的材料

处理口径：
1. 先接受“主题词搜索适合找素材池，不适合直接当精品包”
2. 首轮只抓 `content`/`fxgc` 有实质分析、长度够、正文里真出现执行主题词的结果
3. 抓完后默认再做一轮二筛，按主题分成：`恢复执行` / `首查封-处置权-主持分配法院` / `参与分配-分配方案异议` / `执行监督`
4. 二筛时优先保留：能回答程序分流、文书动作、法院权限边界的样本；弱相关、纯结果型、标题过泛的材料可以降级或剔除

经验判断：**这类执行案例更适合先批量抓一桶，再人工/主 agent 二筛；别指望一次检索就全是高密度好货。**

## 多方向并行扩库模式（2026-04-27 验证）

适用场景：
- 桌面策略文档/积分记录中定义了"下一轮转向"的多个新方向（如 3 个方向）
- 不是已知名称清单，而是战略主题（如"行政许可衔接""建工招投标争议""数据合规"）
- 需要同时跑多个方向，不串行逐条

### 标准流程
1. **读策略文档**：确认当前已够用的线、已停止深挖的线、下一轮新方向
2. **本地去重**：对每个新方向的关键主题词批量搜索 `~/Documents/知识库/raw/notes/`，确认哪些已有、哪些缺
3. **规则层补库**：对每个方向，搜索目标法规 → 筛候选 → 取详情 → 保存。已有则跳过
4. **案例层补库**：每个方向按 `search_qwal(权威案例)` + `search_ptal(江苏案例)` 拉取。优先 content > 500 的结果直接保存
5. **落盘到独立批次目录**：`yuandian_batch_YYYY_MM_DD_roundN_newdir/` + `cases/` 子目录
6. **同步更新桌面文档**：积分记录 + 策略与方案文档，追加本轮结果

### 案例检索 API 坑
- `search_qwal` 和 `search_ptal` 的 `qw` / `ay` 参数不支持中文列表格式传多个值（如 `ay="招标投标纠纷"` 会报 syntax error）
- 正确做法：`qw="关键词1 关键词2"` 用空格分隔，`ajlb="民事案件"/"行政案件"` 用单值
- `xzqh_p` 参数必须传列表：`["江苏"]`，不能传 `"江苏"` 字符串（会报 syntax error）
- **`ay` 参数极度不稳定**：实测传任何中文案由名都报 `syntax error`，完全不要用。只靠 `qw` 做关键词匹配
- **`qw` 的中文关键词组合可能随机报 syntax error**：同样的调用格式，某些中文组合（如 `"行政许可 撤销 程序违法"`）报 syntax error，但另一些组合正常。遇到 syntax error 时：先简化关键词（减到2-3个词），或换另一组同义词重试，或改走 `search_fagui` 查规则层
- `search_qwal` 返回的权威案例 content 普遍较短（300-800 chars），能反映要旨即可保留，不必追详情。若 content < 200 且主题重要，再调 `get_case_detail(type='qwal', id=...)`

### 经验判断
- 多方向并行扩库时，积分消耗按 规则×20分/条 + 案例×10分/条 估算
- 一个方向已有主法（如行政强制法、行政复议法）时，优先补配套实施条例/程序规则
- 案例层权威案例 content 普遍较短（300-800 chars），能反映要旨即可保留，不必追详情
- 每个方向首轮控制在 法规 2-5 条 + 案例 8-15 条，够用就停

### 自动清理低价值文件
多轮扩库后会混入低价值文件，每轮落盘后应自动清理：
- **培训/研修班通知**：含"研修班"、"培训班"、"培训通知"
- **征文/评选通报**：含"征文"、"评选结果"、"通报"
- **律协/行业会议通知**：含"律师协会"、"研讨会"、"研修班"
- 判断逻辑：文件名含上述关键词 + content < 5000 chars → 直接删除，不入包

### 边际递减硬阈值
连续 3+ 轮扩库后，若本地已有 80%+ 的目标规则，说明该领域底层已饱和，应停止扩库转向整库治理。
- 第 19 轮实测：人身损害赔偿方向 10 条目标规则中 9 条本地已有（90%），只补到 1 条新规
- 信号：规则层补不到新东西 + 案例层产出的都是程序件 → 立即转入治理阶段

### 已验证的高价值新方向主题
以下主题在 5 轮扩库中确认高价值，后续如需继续扩库可参考：
- **金融消保**：适当性义务、理财产品销售、银行保险消保管理办法
- **反垄断**：2025 修正的禁止垄断协议规定、禁止滥用市场支配地位行为规定
- **知产侵权**：惩罚性赔偿解释、商业秘密侵权
- **担保实务**：民法典担保制度司法解释（核心）
- **人身损害**：本地基础已好，以案例层为主

## 质量筛选

下载后要区分法规正文 vs 周边文件：

法规正文特征：
- 名称简洁，不含"关于"、"通知"、"答复"、"批复"、"公告"
- 效力级别是"法律"、"行政法规"、"司法解释"、"部门规章"

周边文件特征：
- 名称含"关于"、"通知"、"答复"、"批复"、"公告"
- 效力级别可能是"其他"

```python
# 质量判断
noise_keywords = ["关于", "通知", "答复", "批复", "公告", "对", "人大", "政协", "复函"]
is_real_fagui = not any(kw in name for kw in noise_keywords)
```

## 标准流程

0. **判断模式**：
   - 用户有明确法规名称清单 → 走"精确名称批量下载"（步骤 0b 起）
   - 桌面策略文档定义了"下一轮新方向"（多个战略主题） → 走"多方向并行扩库模式"（见上方章节）
0b. **先对照本地库去重**：先搜索 `~/Documents/知识库/raw/notes/`、`wiki/sources/`，把清单分成"本地已有 / 本地缺失 / 仅有旧版或摘要"。不要拿旧待下载清单直接开下，里面经常混着已入库项目。
1. 整理精确名称清单（或用效力级别过滤）
2. 若用户是在做“积分规划”而不是立刻下载，先按专题做缺口盘点：全国常用法源、江苏地方规范、江苏执行/行政、高频案由案例；优先下载真正能扩库的缺口，不要被历史 backlog 牵着走。
3. 批量调用 API 下载
4. 质量筛选：法规正文 → 主库，周边文件 → 子目录或删除
5. **自动清理低价值文件**：扫描批次目录，删除含"研修班/培训/征文/评选/律师协会"等关键词且 content < 5000 chars 的文件
6. 更新知识库索引
7. 同步更新桌面文档：追加到 `元典积分使用记录.md` 和 `元典下载策略与方案.md`
8. 汇报：成功数量、质量比例、低价值清理数、剩余积分

## 积分规划补充

当用户问“这几万/几十万积分怎么花”时，别只复述旧清单，要先做一次本地核查。

已验证的高价值做法：
- 先核对旧记录中的“未下载清单”是否已有重复项
- 再按主题盘点本地覆盖：全国常用法、司法解释、江苏地方规范、江苏案例
- 通常更值的增量，不是继续补一串全国通用法，而是补**江苏执行 / 江苏行政 / 江苏本地典型案例**这类本地明显偏薄的层
- 规划文档里要显式标出“本地已有，不必重复烧积分”的项目

## API 调用约束

- 每次调用 10 分积分
- `search_fagui` top_k 最大 50
- 失效法规也会返回，标注 `sxx="失效"`
- 部分"程序处理异常"是库未收录

## 新站实战补充（2026-04-27）

### 1. `get_fagui_detail(fgmc=精确名称)` 不能盲信
新站会出现两类坑：
- 直接返回 `程序处理异常`
- 按名称返回了一个“通知外壳/印发通知”，而不是真正想要的规范正文

已踩中的典型例子：
- `前期物业管理招标投标管理暂行办法` → 命中成 `建设部关于印发《前期物业管理招标投标管理暂行办法》的通知`
- `物业服务收费明码标价规定` → 命中成 `江苏省物价局关于印发《物业服务收费明码标价规定》的通知`
- `江苏省政府信息公开暂行办法` → 命中成 `江苏省人民政府关于印发江苏省政府信息公开暂行办法的通知`

所以默认策略应改为：
1. 先尝试 `get_fagui_detail(fgmc=精确名称)`
2. 若返回异常，或标题含 `通知/答复/批复/公告/复函`，直接判为**不可直收**
3. 改走 `search_fagui(fgmc=名称, top_k=10)` 或更稳的关键词检索
4. 对候选结果按以下顺序筛选：
   - 标题等于目标名称或高度接近
   - `xljb_1` 属于 `法律 / 司法解释 / 行政法规 / 部门规章 / 地方性法规 / 地方政府规章`
   - 标题不含 `通知 / 答复 / 批复 / 公告 / 复函 / 函`
   - `sxx` 优先 `现行有效`
5. 只有通过这轮筛选的，才取详情并入库

### 2. 江苏地方规范要接受“通知外壳承载正文”这个现实，但别直接当正式正文
有些江苏地方规则在元典里就是通过“印发通知”承载。处理口径：
- 下载时可先保留，标记为“待二筛”
- 入主库前必须区分：
  - 真正的地方性法规 / 地方政府规章 / 高院规则正文
  - 只是印发该文件的通知壳
- 不能因为正文附在通知里，就把通知壳直接当成最终高质量法源页

### 2.5 江苏高院“同主题指南”要防串档，低置信目标宁可跳过
新站在江苏执行线的高院指南上，除了“通知外壳”问题，还有一类更恶心的坑：**同主题、近标题、同系统文件会互相串档。**

已再次踩中的例子：
- 目标：`江苏省高级人民法院执行异议及执行异议之诉案件审理指南(三)`
- 实际返回：`江苏省高级人民法院审查类执行监督案件办理程序指南`

这类情况说明：
1. 不能因为返回文件同属“江苏高院 + 执行”就当作命中
2. 如果目标标题中的核心识别词（如 `指南(三)`、`执行异议之诉`）没有同时命中，默认判为**串档失败**
3. 对这类低置信目标，宁可记为 `skipped / 未稳定命中`，也不要硬写成“已下载”
4. 若同一目标连续两轮都串档，说明这条不适合继续硬撞，应改用案例补强或公开来源补位

经验判断：**江苏高院同线指南一旦出现串档，继续死磕通常只会白烧积分。**

### 3. API 客户端要加非 JSON 容错
新站偶尔会返回非 JSON 内容；`resp.json()` 会直接炸。实际代码层面应给 `_post/_get` 补一层：
- `try: resp.json()`
- `except:` 打印 `HTTP 状态码 + resp.text 前 300 字`
- 然后返回 `None`

不做这层保护，批量任务会被一个烂响应整段打死，很烦。

### 4. 多 Key 轮换
如果用户有多个元典 API Key：
- 默认通过环境变量提供 key，必要时临时写入 `<skill-install-dir>/yuandian-legal-search/scripts/config.py`
- 一把 key 用到余额异常、配额异常或用户要求切换时，再换另一把
- 记录本轮使用的是哪把 key，避免后面算不清积分去哪了

### 5. 旧清单里的“未见/缺口”别照单全收，先重新对本地库
桌面策略文档、积分记录、历史缺口清单很容易过期。继续下载前，先按目标名称批量搜索 `~/Documents/知识库/raw/notes/`，把项目分成三类：
- 已有正文：直接跳过，不重复烧积分
- 已有但只是通知外壳 / 附件型正文：标记为“待二筛”，不要再按“未见”处理
- 真缺失：才进入元典下载队列

实战里已经出现过：`住宅专项维修资金管理办法`、`证券投资基金法`、`对外贸易法`、`进出口关税条例`、`海关稽查条例` 等在旧文档里写着缺口，但本地其实已经有了。


### 7. 专题深挖时，默认按“规则层 + 权威案例 + 地方高质量样本”三层抓，不要只堆一桶 case
当用户不是要零散下载，而是要把某几个案由/争点做成可办案调用的专题包时，默认改成三层结构：
1. **规则层**：主法 / 司法解释 / 指导规则 / 审理指南 / 指导意见
2. **权威案例层**：指导性案例、典型案例、公报案例、巡回法庭参考案例
3. **地方高质量样本层**：优先江苏；重点抓判决书和有实质分析的二审/再审样本

推荐做法：
- 每个专题先明确 2~4 个细争点，再按争点搜，不要只用大词扫一遍。
- 先补规则层，再抓权威案例，最后补地方样本。
- 汇报时按专题分组，不要把不同案由的法规和案例混成一张散清单。

已验证适用的专题：
- 物业纠纷：物业费抗辩、空置房/未入住抗辩、前期物业合同效力、服务瑕疵减免
- 公司解散：公司僵局、经营管理严重困难、其他救济先行、强制清算衔接
- 公司股权转让：合同效力、工商变更对抗、优先购买权、代持/瑕疵股权
- 行政处罚：程序违法、证据不足、裁量不当、听证告知/送达/期限瑕疵
- 业委会：业主撤销权、知情权、业委会与物业合同衔接

### 8. 行政处罚案例要主动避开“非诉审查垃圾池”
对 `行政处罚` 做普通案例检索时，直接搜大词很容易掉进：
- 行政非诉审查裁定书
- 非诉执行审查裁定书
- 行政确认/行政复议边缘材料

处理口径：
1. 优先检索词带争点，如：`行政处罚 撤销`、`行政处罚 程序违法`、`行政处罚 证据不足`、`行政处罚 听证`。
2. 普通案例优先保留：
   - 行政判决书
   - 明确讨论处罚程序、证据、裁量、期限、告知义务的材料
3. 默认排除：
   - 标题含 `非诉`、`执行审查`
   - 只有程序动作、没有处罚合法性分析的裁定书
4. 若检索仍混入边缘案，汇报时要明确标注“可参考，但不是本专题核心样本”。

### 9. 公司解散与股权转让主题要做跑偏剔除
这两条线很容易搜着搜着歪掉：
- 公司解散 → 混入股东出资纠纷、一般公司治理纠纷
- 股权转让 → 混入执行异议、再审通知、与股转只有边缘关系的材料

精筛规则：
1. `公司解散` 默认优先保留标题或正文明确出现：
   - `公司解散纠纷`
   - `公司僵局`
   - `经营管理严重困难`
   - `强制清算`
2. `公司股权转让` 默认优先保留标题或正文明确出现：
   - `股权转让纠纷`
   - `股权转让合同`
   - `优先购买权`
   - `工商变更`
3. 对只有边缘关联的材料：
   - 可以暂存，但要标为“交叉参考/边缘样本”
   - 不要和核心样本混列

### 10. 业主大会和业主委员会指导规则这类文件，允许“通知外壳 + 附件正文”入包，但必须明示
实战已再次验证：
- `业主大会和业主委员会指导规则` 很可能只能稳定命中为 `住房和城乡建设部关于印发《业主大会和业主委员会指导规则》的通知`

处理口径：
1. 如果 detail 的 `content` 带完整附件规则正文，可下载保留。
2. 文件元信息或汇报里必须明确标注：`通知外壳/附件型正文`。
3. 不要把它说成“纯净规章正文已命中”；事实不是。

### 11. 强制清算专题别只搜“强制清算”，地方样本优先改抓“清算责任 / 股东损害公司债权人利益责任”
实战补充：继续死搜 `强制清算`，权威案例还能出货，但地方样本很容易发散或偏空。更稳的地方案本入口反而是：
- `清算责任纠纷`
- `股东损害公司债权人利益责任纠纷`
- `清算义务人`
- `怠于清算`

处理口径：
1. 权威层仍可用 `强制清算` / `公益清算` / `公司清算` 抓典型案例。
2. 地方样本层优先改搜上面四类责任争点，不要只盯标题里有没有“强制清算”。
3. 抓到的样本如果核心在清算义务、怠于清算、债权人损害责任，即使标题不是“强制清算案”，也可视为本专题核心样本。
4. `最高人民法院关于审理公司强制清算案件工作座谈会纪要` 若连续多轮都不稳定命中，默认停止死磕，改用权威案例+责任样本补位。

### 12. 空置房 / 未入住抗辩，样本搜索词优先“未入住 物业费”，同物业公司成组样本有价值
实战补充：`空置房 物业费` 能出样本，但 `未入住 物业费` 往往更容易拉到可用判决书。

处理口径：
1. 先用 `未入住 物业费`，不够再退回 `空置房 物业费`。
2. 结果里如果出现同一物业公司对多个业主的成组判决，不要嫌它重复；这类材料反而适合观察法院对同类抗辩的稳定口径。
3. `前期物业管理招标投标管理暂行办法` 如果连续多轮都不稳定命中，默认视为元典侧高摩擦目标；不要为了补一条规则继续硬烧积分。
4. 这条线在规则层缺一角时，可先用 `物业管理条例`、`物业服务纠纷司法解释`、`住宅专项维修资金管理办法` 先撑住专题骨架。

### 13. 行政处罚“裁量 / 证据”要接受高漂移现实，不够准就停，别强行凑数
实战补充：即便把检索词压到 `证据不足`、`裁量过重`、`撤销处罚`，元典结果仍会频繁漂向：
- 行政复议
- 行政受理
- 其他行政行为
- 边缘程序案

处理口径：
1. 能明确讨论 `证据不足`、`事实不清`、`处罚明显不当`、`撤销处罚` 的，才算核心样本。
2. 复议案、受理案、其他行政行为案，如仅有边缘参考价值，要单独标注“交叉参考/边缘样本”，不要混进核心包。
3. 如果一轮精筛后仍主要是边缘案，宁可少收，也不要为了看起来热闹硬凑满数量。
4. 当专题连续多轮出现这种高漂移，优先考虑转入整理阶段：把现有规则层 + 少量硬样本收束成可调用专题包，而不是继续机械增量。

### 14. 子专题挖到边际递减后，要及时切回别的高频内容，不要恋战
实战补充：当某条线已经补出一批规则层 + 权威案例 + 地方样本，而新增结果开始明显变水、重复、串档或边缘化时，继续深挖往往不划算。

处理口径：
1. 一旦出现“连续两轮新增质量下降、边际收益变低”，默认停止在该子专题继续硬挖。
2. 及时切回其他高频内容，优先顺序可参考：`劳动争议`、`民间借贷`、`建设工程施工合同纠纷`、`婚姻继承`。
3. 文档更新时重点写三件事：
   - 本轮新增了什么
   - 哪些目标不再继续硬撞
   - 下一轮转向什么
4. 不要继续复用旧的“未见/缺口”清单；这类清单过一轮就容易过时。

### 15. 转向高频广谱内容时，精确标题检索也会串到案例/旧问答，必须做标题验真
实战补充：从专题深挖切回高频广谱内容后，`search_fagui(fgmc=精确标题)` 也不一定老实。已再次踩中的例子：
- 目标想下 `劳动争议解释(一)`，结果可能串到 `最高法发布六件劳动争议典型案例`
- 目标想下 `婚姻家庭编解释(一)`，结果可能串到 `最高人民法院对于婚姻继承等有关问题的来问之解答`

处理口径：
1. 不要因为 `xljb_1=司法解释` 就放松警惕；仍要核对标题是否真等于目标标题。
2. 若返回标题明显是“典型案例 / 来问解答 / 新闻发布”，默认判为**替代命中**，不能冒充原目标规则。
3. 可保留这类替代命中，但汇报与批量总结里必须单独标明，不要混写成“已补到目标解释”。
4. 转向广谱内容时，适合补真正稳定命中的目标，如：
   - 民间借贷规定
   - 建设工程施工合同解释
   - 其他能稳定按精确标题命中的高频法源
5. 对明显不稳定的目标，宁可记为“待复核/待换源”，也别为凑清单硬收错文件。

### 15. 多轮扩库节奏与边际递减阈值
一轮扩库不要只盯一个专题，建议按"3 个新方向并行"节奏跑。
当连续两轮出现以下信号时，默认停止扩库，转入整库治理（转交 `legal-kb` 的 maintenance/governance 流程）：
- 单轮命中新规则数 ≤ 2 条（其余均为本地已有）
- 搜索返回的通知/答复/培训类低价值文件比例 > 30%
- 同一领域深挖连续多轮产出 < 3 条高价值材料

已验证的扩库方向质量排序（高质量 → 边际递减）：
- **高价值**：金融消保（银行消保办法 6954 chars、理财办法 22472 chars）、反垄断 2025 修正（8673 chars）、担保制度司法解释（15901 chars）、行政协议司法解释
- **中价值**：招投标案例补强、数据合规细化（跨境流动规定、汽车数据）、商业秘密案例
- **边际递减明显**：人身损害赔偿（核心规则本地已有 90%）、破产实务（规则层本地已有 90%）、税务争议

### 16. 扩库后整库治理最小动作集
扩库累计 5-6 轮后，本地会产生大量散落的 `yuandian_batch_*` 目录，治理前必须做三件事：
1. **合并批次目录**：将所有 `yuandian_batch_*/cases/` 文件移入 `raw/notes/`，消除 30+ 层嵌套
2. **内容去重**：对移入后的文件做 MD5 比对，删除完全重复项
3. **清理低价值文件**：删除培训通知、个案执行通知书、无实质内容的答复件

治理完成后更新 `wiki/index.md` 头部状态摘要。具体深度治理（索引修复、source 补页、专题收口）转交 `legal-kb` 的 maintenance/governance 流程。
