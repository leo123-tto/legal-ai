# 元典批量下载规则

本文件用于清单式下载法规、案例或专题材料时控制质量和积分消耗。原则是：先查本地、再查元典；先检索、再详情；先筛候选、再入库。

## 适用场景

- 用户提供法规或案例清单，希望批量补入本地知识库。
- 用户要围绕某个专题补法规、案例、地方规则。
- 用户希望用元典补齐 `gap-log.md` 中的高价值缺口。
- 需要在积分有限时提高命中质量，避免下载通知、答复、培训通知等低价值材料。

## 固定前置

1. 先用 `legal-kb` 搜索本地知识库，确认目标是否已存在。
2. 对每个目标标记为：`本地已有` / `本地摘要或旧版` / `本地缺失`。
3. 只对“本地缺失”或“本地只有低质量摘要”的目标使用元典。
4. 查询结果优先缓存，正式入库仍走 `legal-kb` 的 raw/source 流程。
5. 每次调用前提醒：元典 API 可能消耗积分。

## 法规下载流程

### 已知精确标题

不要直接用简称撞详情接口。更稳的顺序：

1. `search_fagui(fgmc=精确名称, sxx="现行有效", xljb_1=目标效力级别, top_k=5)`
2. 若无结果，再降级为 `keyword=精确名称`。
3. 本地筛候选：标题、效力级别、时效性、发布机关、是否通知外壳。
4. 只对高置信候选调用 `get_fagui_detail(id=...)`。

```python
from yuandian_api import search_fagui, get_fagui_detail

results = search_fagui(
    fgmc="住宅专项维修资金管理办法",
    xljb_1="部门规章",
    sxx="现行有效",
    top_k=5,
)

for item in results or []:
    if item.get("fgmc") == "住宅专项维修资金管理办法":
        detail = get_fagui_detail(id=item["id"])
        break
```

### 只知道主题

对“执行异议审理指南”“行政处罚听证规则”“参与分配指导意见”这类主题材料，不要靠单一标题硬撞。

- 搜索词用主题词组合，如：`执行异议 审理指南`。
- 默认 `search_mode="AND"`。
- 按任务选择 `xljb_1`：`法律` / `司法解释` / `部门规章` / `地方司法文件` / `地方性法规` / `地方政府规章`。
- 回来后按标题、发布机关、地区、时效性二次筛选。

### 通知外壳处理

有些规范以“关于印发……的通知”承载。处理口径：

1. 先看 `content` 是否包含完整附件正文。
2. 有完整附件正文：可保留，并标记“通知外壳/附件型正文”。
3. 只有通知壳、没有实质条文：不入主库，可记录为低价值候选。
4. 不能把通知壳说成“已命中纯净法规正文”。

## 案例下载流程

案例不一定需要拉全文。很多检索结果里的 `content` 或 `fxgc` 已经足够判断价值。

### 权威案例优先

```python
data = search_qwal(qw="关键词", xzqh_p=["江苏"], top_k=10)
```

保留标准：

- 有裁判要旨、典型意义、指导意义。
- 能回答具体争点。
- 内容长度足够，且不是纯程序信息。

### 普通案例补充

```python
data = search_ptal(
    qw="关键词",
    xzqh_p=["江苏"],
    wszl="判决书",
    top_k=10,
)
```

优先保留：

- 正文包含“本院认为”“裁判分析”“应当认定”“不予支持”等实质分析。
- 与目标争点直接相关。
- 案由、法院层级、地区对用户工作有复用价值。

默认排除：

- 只有程序动作、没有裁判规则的裁定书。
- 标题泛化、正文过短、无法形成办案参考的材料。
- 与目标争点只是弱相关的边缘样本。

## 专题补库流程

做专题时按三层抓，不要只堆案例：

1. **规则层**：主法、司法解释、指导规则、审理指南、地方规则。
2. **权威案例层**：指导性案例、典型案例、公报案例、参考案例。
3. **地方样本层**：优先用户所在地区或高频办案地区，重点抓有实质分析的判决。

每个专题先明确 2-4 个细争点，再分别检索。汇报时按争点分组，不要把法规和案例混成散清单。

## 质量筛选

### 法规正文特征

- 名称简洁，通常不含“关于”“通知”“答复”“批复”“公告”。
- 效力级别为法律、行政法规、司法解释、部门规章、地方性法规、地方政府规章等。
- 正文包含完整条文结构。

### 周边文件特征

- 名称含“通知”“答复”“批复”“公告”“复函”等。
- 内容主要是转发、印发、征求意见、培训、会议或评选。
- 即使命中关键词，也不直接作为高质量法源入库。

```python
noise_keywords = ["培训", "研修班", "征文", "评选", "会议通知", "律师协会"]
if any(token in title for token in noise_keywords):
    mark_as_low_value = True
```

## 积分控制

- 检索够用时，不调详情。
- 详情只调高置信候选。
- 分页接口设置上限，默认不要无限翻页。
- 同一目标多次失败时，停止硬撞，改用公开来源或登记待人工补充。
- 批量结束后汇报：检索目标数、详情调用数、成功入库候选数、跳过原因。

## 入库与汇报

批量下载后不要直接把所有结果塞进知识库。先分三类：

- `可入库`：正文完整、来源清楚、与目标强相关。
- `待复核`：疑似通知外壳、标题近似、正文可用但来源形态复杂。
- `跳过`：培训、征文、会议、弱相关、纯程序信息、重复材料。

正式入库时转交 `legal-kb`：

1. 写入 `raw/notes/` 或 `raw/yuandian-cache/`。
2. 生成或维护 `wiki/sources/`。
3. 保留 API 调用时间、来源接口、检索词和筛选理由。
4. 更新索引、日志或 `gap-log.md`。

## 常见异常

| 场景 | 处理 |
|---|---|
| 精确标题命中通知外壳 | 看附件正文是否完整；不完整则跳过 |
| `get_fagui_detail(fgmc=...)` 返回异常 | 改用 `search_fagui` 找候选，再按 `id` 拉详情 |
| 案例 `ay` 参数报错 | 改用 `qw` 关键词组合 |
| `xzqh_p` 报错 | 传列表，如 `["江苏"]` |
| 非 JSON 响应 | 记录 HTTP 状态和响应前 300 字，跳过该项 |
| 同专题结果开始大量重复或低价值 | 停止扩库，转入 `legal-kb` maintenance 整理 |

## 注意事项

- 不要用简称或模糊关键词直接下载详情。
- 不要为了凑数量把低价值材料入库。
- 不要把旧待下载清单当成当前事实，先重新查本地库。
- 不要把元典结果替代正式法律核验；重要结论仍需核对原文、时效和权威来源。
