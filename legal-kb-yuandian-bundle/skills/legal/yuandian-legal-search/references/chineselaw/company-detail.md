# 元典企业详情接口

接口用途：根据企业 ID 或统一社会信用代码获取目标企业的工商登记、人员、股东、变更、知识产权、涉诉和风险等信息。

## 接口要点

| 项 | 值 |
|---|---|
| HTTP Method | `GET` |
| URL | `https://open.chineselaw.com/open/rh_company_detail` |
| 鉴权 | Header `X-API-Key: <key>` |
| 入参 | `id` 或 `tyshxydm`，二选一 |
| 返回 | 单个企业详情对象 |

## 使用方式

本包不提供单独 CLI，推荐在 agent 中通过 `yd_ref` 调用：

```python
import sys
sys.path.insert(0, "scripts")
import yd_ref

detail = yd_ref.get_company_detail(tyshxydm="91110108MA0074PN30")
# 或
detail = yd_ref.get_company_detail(id="企业ID")
```

如果只有公司名称，先用 `enterprise_search` 或 `get_company_info` 锁定主体，不要直接把名称当作详情接口入参。

## 返回字段

常见字段包括：

- 基础标识：`企业ID`、`企业名称`
- 工商登记：`法定代表人`、`统一社会信用代码`、`注册资本`、`企业类型`、`成立日期`、`登记机关`、`注册地址`、`经营状态`、`经营范围`
- 人员：`董事`、`监事`、`经理`、`董事长`、`财务负责人`、`核心成员`
- 股东：`股东`、`股东详情`
- 变更：`变更`
- 知识产权：`商标`、`软件著作权`、`专利`、`知识产权`
- 涉诉与风险：仅在有数据时返回
- 分支机构、对外投资：仅在有数据时返回

字段动态存在，必须用 `.get()` 容错，不能假设每个 key 都存在。

## 数据质量注意

1. 字段可能缺失，不代表一定没有对应事项。
2. 列表类字段可能有返回上限，不能视为完整尽调清单。
3. 日期格式可能混杂，写入底稿前应统一。
4. 金额和注册资本常带单位，不能直接数值计算。
5. 股东出资额可能为空，应以章程、验资报告、工商档案等材料核实。
6. 重名问题必须在调用前解决，优先用企业 ID 或统一社会信用代码。

## 章节使用规则

| 章节 | 用法 | 注意 |
|---|---|---|
| 主体资格 | 基础工商登记信息 | 与营业执照、章程核验 |
| 股权结构 | 股东、股东详情 | 出资额为空时写明待核实 |
| 治理组织 | 董监高、核心成员 | 任职文件仍需用户材料 |
| 核心资产 | 商标、专利、软著 | 避免与聚合字段重复计算 |
| 诉讼行政执行 | 涉诉、风险字段 | 仅作线索，必要时调用专项接口 |
| 对外投资 | 分支机构、对外投资 | 仅作线索，必要时翻页补查 |

## 引用规范

固定模板：

> 经查阅元典开放平台「企业详情」接口（调用时间 YYYY-MM-DD HH:MM，原始数据见 `raw/chineselaw/...`），目标公司基本工商登记信息如下：……

如关键字段与目标公司提供材料冲突，应写明冲突并列入风险提示或待核验事项，不能直接覆盖用户材料。

## 失败处理

| 场景 | 处理 |
|---|---|
| 参数异常 | 检查是否同时缺少 `id` 和 `tyshxydm` |
| 未命中 | 记录“元典库未命中”，改用国家企业信用信息公示系统或用户证照 |
| 网络/超时 | 记录调用时间和失败原因，必要时重试 |
| 凭证缺失 | 不写入底稿，先提醒配置 API |
